SMathFtoolBridge

O diagrama estrutural do Ftool vive dentro da sua planilha do SMath Studio. Duplo clique abre o modelo para editar; um clique traz a imagem atualizada de volta. Sem exportar arquivo, sem print manual, sem colar imagem.

versão 1.0.0.0 alvo SMath 1.5.x .NET Framework 4.8 instalação sem admin

01 O problema

Quem faz memorial de cálculo estrutural trabalha em duas janelas ao mesmo tempo.

O Ftool é onde o pórtico é modelado e analisado. O SMath Studio é onde o cálculo é documentado. O diagrama precisa aparecer no memorial — e o caminho normal para isso é manual e repetitivo: 

# a cada ajuste no modelo, de novo:
Ftool  → Arquivo → Export Model Screen → salvar imagem
SMath  → Inserir imagem → escolher o arquivo → reposicionar
       → apagar a imagem velha

E como a imagem é só um arquivo colado, ela não tem vínculo nenhum com o modelo. Meses depois ninguém sabe qual .ftl gerou aquele diagrama, nem se a imagem ainda corresponde ao modelo atual.

A ideia do plugin: transformar o diagrama numa região nativa da planilha, que guarda o caminho do .ftl junto com o documento e sabe conversar com o Ftool aberto.

02 Como funciona, na prática

O ciclo inteiro acontece dentro do SMath, pelo menu de contexto.

Inserir > Ftool Você escolhe um arquivo .ftl e a região já entra vinculada a ele. Numa região que já existe, o vínculo se troca pelo menu de contexto.
Duplo clique abre o Ftool Com o .ftl vinculado carregado. Se já houver uma janela do Ftool aberta com esse arquivo, ela é trazida para a frente em vez de abrir outra.
Você ajusta o modelo No Ftool, normalmente. Sem precisar salvar nem exportar nada.
"Sincronizar com o Ftool aberto" De volta ao SMath, o plugin captura a janela do Ftool, recorta sozinho só a área do desenho e atualiza o preview na planilha.

O preview não se atualiza sozinho. Ele é uma imagem estática: depois de mexer no modelo, é sempre o Sincronizar que traz o desenho novo. Essa é a etapa que mais confunde quem usa o plugin pela primeira vez.

03 O que a região faz

Vínculo persistente

O caminho do .ftl é salvo junto com o documento .sm. Reabrir a planilha meses depois mantém a ligação com o modelo.

Recorte automático

A captura pega a janela inteira do Ftool; o plugin acha o canvas do desenho e descarta menus, barras e painel lateral.

Recorte manual fino

Cortar topo, base, esquerda ou direita por porcentagem, várias vezes seguidas, com desfazer do último passo ou de todos de uma vez.

Proporção preservada

A imagem nunca estica. O desenho é encaixado em letterbox dentro da região, mesmo com recorte assimétrico.

Zoom por comando

Ampliar e Reduzir multiplicam o tamanho por 1,25× / 0,8×, e o tamanho escolhido sobrevive às sincronizações.

Ftool lembrado

O caminho do Ftool.exe é perguntado uma vez e guardado em %AppData%, reconfigurável pelo menu Serviço/Tools.

04 Instalar

Pré-requisito: SMath Studio e Ftool já instalados (versão normal, não portátil). Não precisa compilar nada.

Feche o SMath Studio Ele carrega os plugins na inicialização e mantém a DLL em uso enquanto está aberto.
Dois cliques em SMathFtoolBridge-Setup.exe Sem pedido de administrador: a instalação é só para o seu usuário, em %AppData%\SMath\extensions\plugins.
Abra o SMath e confirme Em Serviço/Tools deve aparecer "Ftool: configurar caminho do Ftool.exe...". Se apareceu, o plugin carregou.

Para desinstalar, Desinstalar.bat (no zip) apaga a pasta do plugin inteira. Se a instalação falhar, a janela grava um log em %TEMP%\SMathFtoolBridge-install.log.

05 Por dentro: o que deu trabalho

O Ftool não tem API, nem automação COM, nem linha de comando além de "abrir arquivo". E o SDK de plugins do SMath é praticamente não documentado. As decisões abaixo saíram de tentativa e erro com o software real.

Capturar o diagrama sem API

A primeira tentativa foi mandar o Ftool executar o próprio comando de exportar (File > Export Model Screen) por mensagem do Windows (WM_COMMAND). Funcionava num modelo vazio de teste, mas não em modelos reais — mesmo com a janela em foco e esperas de até 60 segundos.

A causa era mais simples do que parecia: a janela do Ftool estava minimizada, e nesse estado não existe imagem renderizada para copiar. A solução final abandona o menu do Ftool e usa PrintWindow, API nativa do Windows, restaurando a janela antes se necessário. Ficou mais robusto porque não depende da versão nem do idioma do menu do Ftool.

Achar o desenho dentro do print

O print traz a janela inteira. Para sobrar só o diagrama, o plugin procura a cor de fundo predominante — o canvas do Ftool é sempre um bloco grande de cor sólida, bem diferente dos painéis ao redor — e recorta o maior bloco contínuo dessa cor, tolerando pequenas interrupções, como a barra de mensagem no topo, para não fatiar o desenho ao meio.

Duas armadilhas do SDK do SMath

Estas só apareceram testando a instalação de verdade — nos dois casos o plugin simplesmente não aparecia, sem erro nenhum na interface:

  • Nunca referencie a DLL de outro plugin. A primeira versão herdava de PictureRegion, que vive na DLL de um plugin nativo — não numa biblioteca do núcleo. Ao carregar o plugin isoladamente por reflexão, o SMath não resolve essa dependência e a carga falha inteira. A região passou a herdar direto de RegionBase e desenhar a própria imagem.
  • Falta um arquivo marcador não documentado. Além da pasta com a DLL e os metadados, o SMath só lista o plugin se existir um config.<versão-do-SMath>.ini ao lado. Isso foi descoberto comparando a pasta do plugin com a de plugins de terceiros já instalados. O instalador gera esse arquivo sozinho, detectando a versão do SMath.
  • Compatibilidade entre versões é frágil. Numa máquina com SMath mais antigo o plugin quebrou por usar um tipo que não existia naquela versão. Como as DLLs do SMath não são assinadas, o plugin carrega contra qualquer versão instalada — e qualquer membro ausente derruba a carga inteira, não só aquele método. A correção foi trocar as APIs de conveniência do SMath por WinForms puro.

Gerar o instalador sem compilador

O executável é montado com o IExpress, que já vem no Windows — nenhuma dependência externa. Duas armadilhas dele custaram caro e ficaram documentadas no script de build: o roteiro .SED é lido em ANSI, então um caminho de projeto com acento faz o build falhar sem mensagem nenhuma; e o programa de AppLaunched precisa ser um dos arquivos empacotados — usar cmd /c setup.cmd faz o instalador abrir e fechar sem instalar nada, também em silêncio.

06 Limitações conhecidas

O que o plugin ainda não faz — dito na cara.

LimitaçãoSituação
Sincronizar exige o Ftool aberto Com o arquivo carregado, no momento do clique. Fechado, o plugin avisa — abra pelo duplo clique primeiro.
O recorte automático não é perfeito Pode sobrar um pouco de barra de ferramentas nas bordas. Existe "Sincronizar (janela inteira, sem cortar)" como saída, mais o recorte manual.
Não redimensiona arrastando a borda Não foi possível pela API de região do jeito que o plugin foi implementado. O zoom fica nos comandos Ampliar/Reduzir.
O caminho do .ftl é absoluto Mover a pasta do documento para outra máquina pode quebrar o vínculo. Guardar caminho relativo depende de descobrir como a região acessa o caminho do próprio .sm.
O preview é estático Não acompanha o modelo sozinho: precisa de um novo Sincronizar.

Próximos passos

  • Redimensionamento arrastando a borda da região.
  • Caminho do .ftl relativo ao documento .sm.
  • Sincronizar automaticamente quando o Ftool aberto pela região é fechado.

07 O repositório

dist/
  SMathFtoolBridge-Setup.exe     instalador de duplo clique
  SMathFtoolBridge-1.0.0.0.zip   mesmo conteúdo, para instalação manual
  SMathFtoolBridge.dll           o plugin
  install.ps1 / uninstall.ps1    scripts de instalação
build/
  make-installer.ps1             gera o .exe e o .zip juntos
docs/
  architecture.md                a referência técnica real do projeto

Para regerar os dois artefatos de distribuição a partir dos mesmos arquivos, de forma que nunca fiquem fora de sincronia: 

powershell -ExecutionPolicy Bypass -File build\make-installer.ps1

Sobre o código-fonte: este repositório distribui o plugin já compilado mais a documentação técnica. O código C# ficou na máquina onde o plugin foi desenvolvido e ainda não foi trazido para cá. Enquanto isso, docs/architecture.md é a referência do projeto: documenta a API do SMath usada, o porquê de cada decisão e as armadilhas que só apareceram testando de verdade.
